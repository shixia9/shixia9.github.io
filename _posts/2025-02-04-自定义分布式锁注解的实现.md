分布式锁能够在分布式系统中控制多个进程或线程对有限共享资源的访问，对于那种并发量高、可用性要求高的部分业务就需要考虑加上分布式锁从而实现并发控制。因此，分布式锁它的核心目标大致为：

1. 互斥性：同一时刻只有一个客户端可以持有锁
2. 可重入性：同一个客户端可以多次获取同一把锁，可具体理解为同一进程id可以多次获取同一把锁
3. 自动释放：分布式锁要支持锁超时释放，避免因进程互相等待而造成死锁
4. 高可用性：锁服务需要具备高可用性，避免单点故障

## Redis基础加锁

redis的基础加锁命令
```sql
SET lock_key unique_value NX PX 30000
```
利用redis键的唯一性和原子性操作来实现锁的获取，其中
+ `NX`：仅当`lock_key`不存在时才设置
+ `PX 30000`：设置的key的过期时间为30000毫秒
+ `unique_value`：全局唯一的标识，如UUID、RequestId等，能够防止误删锁

而由于解锁需要判断`unique_value`再执行 DEL 操作，因此必须保证是原子操作，使用 Lua 脚本
```lua
if redis.call("get", KEYS[1]) == ARGV[1] then
    return redis.call("del", KEYS[1])
else
    return 0
end
```
这样能够保证在删除锁的过程中不会有其它进程干扰，具体在Java应用中，使用`setIfAbsent()`方法即可调用该能力，确保同一时间只有一个服务实例能执行临界区代码
```java
public void deduct() {
    String lock_key = "lock:product_id";
    // 尝试获取锁
    Boolean result = stringRedisTemplate.opsForValue().setIfAbsent(lock_key, "key01");
    if (!result) {
        return log.info("获取锁失败");
    }
    try{
        // 具体业务逻辑
        int stock = Integer.parseInt(stringRedisTemplate.opsForValue().get("stock"));
        if (stock > 0) {
            int new_stock = stock - 1;
            stringRedisTemplate.opsForValue().set("stock", new_stock + "");
            log.info("扣减库存成功，剩余：{}", new_stock);
        } else {
            log.error("扣减库存失败");
        }
    } finally {
        // 释放锁
        stringRedisTemplate.delete(lock_key);
    }
}
```

## Redisson分布式锁

**Redisson**为redis当中部分操作封装成了简单易用的API，保持了简单易用、支持锁重入、支持阻塞等待、Lua脚本原子操作，是相对友好的成熟客户端产品。

对于Redisson实现的分布式锁，可以开箱即用：

```java
RLock lock = redisson.getLock("lock_key");
lock.lock();
try {
    // ...具体业务逻辑
} finally {
    lock.unlock();
}
```

其中的`lock()`为自旋锁，如果进程获取不到该锁，它就会一直阻塞直到获取成功；当该进程拿到锁后，如果未指定它的过期时间`leaseTime`,那么在它持有锁的期间，会基于一个**看门狗机制**进行锁的续期

> **看门狗机制**
>
> Redisson会启动一个后台守护线程（看门狗），锁的默认看门狗超时时间是 30 秒；守护线程每隔 10 秒（锁超时时间的 1/3）检查客户端是否还持有锁，如果是，则自动将锁的超时时间重置为 30 秒；只要客户端实例存活且业务未完成，锁就不会过期。
> 
> 同时，看门狗机制的存在能够保证不会在某个进程持有锁时，如果redis在执行业务过程中宕机，之后就没有进程去释放那个锁；或者当设置锁的EX时间太短，有可能在进程执行业务的过程中锁就被释放，其它进程就可以进来加锁。

除了`lock()`进行加锁外，还包括`tryLock()`尝试获取锁，它可指定等待时间`waitTime`和锁租期`leaseTime`，如果能获取到锁就直接返回true，如果无法获取到锁，他会按照指定的`waitTime`进行阻塞，在这个时间段内他还会再尝试获取锁；如果超过这个时间还没获取到则返回false；如果我们没有指定`waitTime`，那么他就在未获取到锁的时候，就直接返回false。

## 自定义注解实现分布式锁

分布式锁可以通过自己定义的注解`@DistributeLock`来实现的，只在需要使用锁的方法上直接加入这个注解，然后就会以AOP的方式拦截这个方法，进入到我们预先写好的切面方法中。

这个注解主要有以下几个字段：

+ `scence()`：它是业务锁前缀，用来区分不同业务场景下的锁。比如说我们在支付场景下为用户生成支付链接为`scence = "GENERATE_PAY_URL"`，而在用户注册的场景下为`scence = "USER_REGISTER"`。

+ `key()`：它是加锁的key，也就是显式指定锁的key。它的默认值为`"NONE"`，如果读取到默认值，那么就会通过SPEL表达式方法`keyExpression()`动态读取key。

+ `keyExpression()`：这个是使用SPEL表达式动态生成的key，比如：

  ```java
  //SPEL表达式：#insertResult.id
  @DistributeLock(keyExpression = "#payCreateRequest.bizNo", scene = "GENERATE_PAY_URL")
  ```

  它的优先级排在`key()`之后。如果`keyExpression()`也没有成功读取到的话，就会抛异常。

+ `expireTime()`：超时时间（ms），默认情况下不设置超时时间，会自动续期。

+ `waitTime()`：加锁等待时长（ms），默认情况下不设置等待时长，会一直等待直到获取锁。

### 实现思路
1. **定义注解**：定义好我们需要的注解`@DistributeLock`，它将支持SPEL表达式动态生成锁的key
2. **AOP切面**：通过AOP拦截被注解`@DistributeLock`标记的方法，将会自动在该方法执行的前后进行加锁和释放锁
3. **配置Redisson**：集成Redisson客户端，提供具体的锁的实现

### 定义注解

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface DistributeLock {

    /**
     * 锁的场景
     * @return
     */
    public String scene();

    /**
     * 加锁的key，优先取key()，如果没有，则取keyExpression()
     * @return
     */
    public String key() default DistributeLockConstant.NONE_KEY;

    /**
     * SPEL表达式
     * @return
     */
    public String keyExpression() default DistributeLockConstant.NONE_KEY;

    /**
     * 超时时间，毫秒
     * 默认情况下不设置超时时间，会自动续期
     * @return
     */
    public int expireTime() default DistributeLockConstant.DEFAULT_EXPIRE_TIME;

    /**
     * 加锁等待时长，毫秒
     * 默认情况下不设置等待时长，会一直等待直到获取到锁
     * @return
     */
    public int waitTime() default DistributeLockConstant.DEFAULT_WAIT_TIME;
}
```

### AOP切面

在我们AOP拦截了需要加分布式锁的方法后，会进行如下几个步骤：

1. 获取锁key，如果注解中定义了`key()`，就直接使用；如果`key()`为默认值`"NONE"`则转向解析`keyExpression()`表达式：

    ```java
    Method method = ((MethodSignature) pjp.getSignature()).getMethod();
    DistributeLock distributeLock = method.getAnnotation(DistributeLock.class);

    String key = distributeLock.key();
    if (DistributeLockConstant.NONE_KEY.equals(key)) {
        if (DistributeLockConstant.NONE_KEY
            .equals(distributeLock.keyExpression())) {
            throw new DistributeLockException("no lock key found...");
        }

        // 使用Spring EL表达式解析key
        SpelExpressionParser parser = new SpelExpressionParser();
        Expression expression = parser.parseExpression(distributeLock.keyExpression());

        EvaluationContext context = new StandardEvaluationContext();
        // 获取参数值
        Object[] args = pjp.getArgs();

        // 获取运行时参数的名称
        StandardReflectionParameterNameDiscoverer discoverer
                = new StandardReflectionParameterNameDiscoverer();
        String[] parameterNames = discoverer.getParameterNames(method);

        // 将参数绑定到context中
        if (parameterNames != null) {
            for (int i = 0; i < parameterNames.length; i++) {
                context.setVariable(parameterNames[i], args[i]);
            }
        }
        // 解析表达式，获取结果
        key = String.valueOf(expression.getValue(context));
    }
    ```
2. 将解析出来的`scene`和`key`通过`#`拼接在一起构建锁，并设置锁的过期时间和加锁等待时长。
3. 利用redisson拿到锁，然后开始加锁，这里会出现几种情况：
    + 如果没有设置等待时间`waitTime`，就使用阻塞锁`rLock.lock()`
    + 如果设置了等待时间`waitTime`，就使用尝试锁`rLock.tryLock()`
    
    对于过期时间`expireTime`，两种锁都可以设置，在这两个锁的基础上再做个判断就好了
4. 如果获取锁失败`!lockResult`，直接抛异常，记录下日志；成功获取了锁，就可以放行执行自己的业务方法：`response = pjp.proceed()`

    ```java
    // 构建锁
    String scene = distributeLock.scene();
    String lockKey = scene + "#" + key;
    int expireTime = distributeLock.expireTime();
    int waitTime = distributeLock.waitTime();
    RLock rLock= redissonClient.getLock(lockKey);

    try {
        boolean lockResult = false;
        if (waitTime == DistributeLockConstant.DEFAULT_WAIT_TIME) {
            if (expireTime == DistributeLockConstant.DEFAULT_EXPIRE_TIME) {
                // 无waitTime，无expireTime
                log.info(String.format("lock for key : %s", lockKey));
                rLock.lock();
            } else {
                // 无waitTime，有expireTime
                log.info(String.format("lock for key : %s , expire : %s", lockKey, expireTime));
                rLock.lock(expireTime, TimeUnit.MILLISECONDS);
            }
            lockResult = true;
        } else {
            if (expireTime == DistributeLockConstant.DEFAULT_EXPIRE_TIME) {
                // 有waitTime，无expireTime
                log.info(String.format("try lock for key : %s , wait : %s", lockKey, waitTime));
                lockResult = rLock.tryLock(waitTime, TimeUnit.MILLISECONDS);
            } else {
                // 有waitTime，有expireTime
                log.info(String.format("try lock for key : %s , expire : %s , wait : %s", lockKey, expireTime, waitTime));
                lockResult = rLock.tryLock(waitTime, expireTime, TimeUnit.MILLISECONDS);
            }
        }
        // 获取锁失败
        if (!lockResult) {
            log.warn(String.format("lock failed for key : %s , expire : %s", lockKey, expireTime));
            throw new DistributeLockException("acquire lock failed... key : " + lockKey);
        }
        // 加锁成功
        log.info(String.format("lock success for key : %s , expire : %s", lockKey, expireTime));
        response = pjp.proceed();
    }
    ```
5. 执行完自己的业务方法后就需要解锁，在`finally`块中先判断锁是不是自己的（被当前线程所持有），然后再解锁
    ```java
    finally {
        if (rLock.isHeldByCurrentThread()) {
            rLock.unlock();
            log.info(String.format("unlock for key : %s , expire : %s", lockKey, expireTime));
        }
    }
    ```

### 具体使用
在需要使用分布式锁的方法上加上`@DistributeLock`注解，并根据需要配置SPEL表达式以及业务场景，例如，对于订单创建场景下：
```java
@DistributeLock(keyExpression = "#request.identifier", scene = "ORDER_CREATE")
```
对于用户注册场景下：
```java
@DistributeLock(keyExpression = "#telephone", scene = "USER_REGISTER")
```
